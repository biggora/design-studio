# Search Console: исходные показатели и оценка результата

## Снять пригодный baseline

Проверь property нужного домена и фактический доступ. Найди подключённый инструмент; если его нет, используй авторизованный профиль браузера. Не заменяй частные данные GSC поиском `site:` и не извлекай токены браузера.

Запиши для каждой анализируемой страницы:

| Поле | Что сохранить |
|---|---|
| Property | Например, `sc-domain:threadquirk.lv`, проверенное в текущем интерфейсе |
| Страна | Явный фильтр выбранного рынка |
| Тип | Web/text, Web/multimodal, Image и другие доступные типы — отдельно |
| Период | Фактические Start/End и выбранный пресет; дата последнего обновления |
| Страница | Exact URL; при необходимости дополнительно группа URLs containing/regex |
| Метрики | Clicks, Impressions, CTR, Average position |
| Запросы | Видимые строки с метриками и пагинацией; либо No data |
| Контекст | Дата появления страницы, недавние изменения и ограничения данных |
| Доказательство | Снимок интерфейса/таблицы или реальный экспорт с настройками |

Для похожих дизайнов сначала измерь каждый Exact URL. Групповой фильтр — полезная дополнительная сверка, но не подмена индивидуальных данных. Для принтов уместна отдельная проверка Image; если релевантно, добавь multimodal, не смешивая его с Web/text.

В этой сессии пресет «3 months» показывал фактические 25 сентября–3 ноября, а quilting-страницы были созданы 31 октября. Поэтому нельзя объявлять это тремя месяцами истории двух страниц. Проверяй actual dates и жизненный цикл URL каждый раз.

## Интерпретировать без ложных выводов

- При нуле показов выводи CTR/среднюю позицию как «нет содержательной оценки», даже если UI печатает `0%` и `0`. Позиция 0 не является местом в выдаче.
- При нуле кликов отсутствие покупок ничего не говорит о конверсии посадочной страницы.
- Не дели накопленные показы на три автоматически, особенно если принты появились недавно. Это также не оценка месячного спроса всего рынка.
- Видимые query rows могут быть неполными из-за privacy/фильтров/ограничений. Не принуждай сумму запросов совпасть с итогами страницы и не считай скрытые строки доказанным нулём.
- Не диагностируй плохой snippet по нулевым кликам без достаточной истории и учёта позиций. Не называй каннибализацией сам факт существования двух тематически похожих принтов.

## Проверить индексирование

В URL Inspection читай сохранённое состояние именно нужного URL:

- URL is on Google / Page is indexed или конкретная причина исключения;
- user-declared и Google-selected canonical;
- Last crawl, crawled as, crawl allowed, fetch result, indexing allowed;
- известные sitemap/referring pages и существенные enhancement issues.

Отдельно проверь текущий публичный HTTP, robots/noindex и sitemap. `HTTP 200` и наличие в sitemap ещё не доказывают индексирование. Последний crawl — не обязательно дата первой индексации. Время без указанного timezone сохраняй как отображённое, не приписывай ему UTC.

Не смешивай старый снимок Google с сегодняшним HTML: наличие Product в сохранённом crawl и его отсутствие сейчас может отражать изменившиеся/истёкшие подтверждённые цены. Разницу сначала объясни фактами, не объявляй причиной нулевых показов.

Live test и Request indexing используй по необходимости в пределах порученной работы. Не обещай, что запрос переобхода гарантирует индексирование или немедленные позиции. На стадии «подготовить аудит» сами предложения не требуют запроса индексации.

## Что делать с полученными данными

| Наблюдение | Разумный следующий шаг |
|---|---|
| Страница исключена/неправильный canonical | Разобраться с причиной и устранить реальное препятствие до оценки CTR |
| Страница новая, индексирована, показов нет | Уточнить товарное намерение, связи и план наблюдения; не объявлять провал |
| Есть релевантные показы, мало кликов | Смотреть позиции, query mix и snippet; предложить точные изменения |
| Показы по нерелевантному намерению | Исправить соответствие текста/подборки товару; не наращивать чужие ключи |
| Есть клики и переходы в магазин | Отдельно изучать подтверждённые покупки; GSC их не измеряет |

После публикации сохрани T0 и дождись обхода новой версии. Сравнивай сопоставимые отрезки с теми же страной, типом поиска и URL. Например, первые и следующие 28 дней после переобхода; контроль через 4–6 недель — окно наблюдения, не обещание результата. Сезонность и одновременные изменения отмечай как ограничения причинного вывода.

Не добавляй query regex при сборе всех запросов страницы без нужды: он может скрыть полезные неожиданные формулировки. Запланированные автоматические отчёты создавай только по запросу пользователя.

Определения метрик и фильтров: [Google Search Console — Performance report](https://support.google.com/webmasters/answer/7576553?hl=en).
