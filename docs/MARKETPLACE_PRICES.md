# Cached T-shirt prices and Product structured data

Price collection runs in **pod-uploader**, using the owner's existing local browser profiles. Design Studio never requests a marketplace or executes curl during page rendering. It reads the public JSON snapshot from its configured `NEXT_PUBLIC_IMAGES_CDN` instead. No new paid service or storefront database migration is needed.

## Publisher

See pod-uploader `docs/prices.md` and `pod prices refresh --help`. The command uses the existing `LISTINGS_API_TOKEN` to read canonical linked sources from `GET /api/v1/designs/tshirt-prices` (paginated, `?id=<UUID>`, or `?sha256=<file SHA>`). The authenticated response includes the optional file SHA and each source's actual listing `publishedAt`, without inferring it from storefront creation. Both providers use the database facade and active-design filters. Deploy this endpoint before enabling the post-publication hook: it refuses a server that ignores the SHA lookup.

Collection reads the actual T-shirt Product/Offer JSON-LD on Redbubble, TeePublic, Tostadora and Zazzle. Redbubble's generic work page resolves to the same work's Classic T-Shirt, never a shop tile's From price. Some TeePublic pages have unescaped quotes in Product names: only when that Product JSON fails to parse, the collector can read the page's unique `og:url`, `product:price:amount` and `product:price:currency` tags, applying the same listing-ID, positive-amount and currency checks. It does not repair JSON or substitute metadata for a valid but expired offer.

No reviews, identifiers, shipping or return claims are fabricated. CAPTCHA/challenge or two consecutive collection errors stop that account. Use the existing account login flow when human attention is required, then rerun the command. HTTP/collection failures preserve the last verified quote without changing its timestamp.

Successful quotes are saved immediately in the uploader's SQLite, independently of upload jobs. In manual mode, quotes younger than 24 hours are skipped unless `--force` is supplied; selective mode follows its own due queue and daily budget. After collection across all selected accounts, `--publish` writes one mutable R2 object per design, `prices/<storefront UUID>/tshirt-v1.json`, with `{version:1,designId,offers}` and a five-minute public cache policy. Republishing saved quotes does not extend their lifetime. If no usable quotes remain, no empty snapshot is published. Existing image objects retain their year-long immutable policy.

With uploader `prices.enabled: true`, collection follows publication and listings synchronization after browser profiles are released. Missing quotes for those prints are collected first, followed by a bounded selective pass over the catalog. The same pass is available separately with `pod prices refresh --due --publish`; no n8n workflow or OS task is installed. It prioritizes missing prices, ended sales, five deterministic daily controls per platform, groups where a price changed, and a monthly rolling sweep. The default successful-check budget is `max(50, ceil(link count / 30) + 20)`, less links checked today; newly published work is handled in addition to that budget. `--budget` and `--samples` override these bounds. Repeated runs keep the same controls and retry unpublished saved snapshots without visiting marketplaces again. A renewable SQLite lease prevents overlapping price passes.

The envelope and key remain version 1 for rollout compatibility. New observations carry `pricingVersion:2`, optional `regularPrice`, `salePrice`, exact `saleEndsAt`, and `variant: "default options"`. Identity and currency are verified against the product; price amounts are read from the visible primary product block. TeePublic supplies both prices and its exact timer attribute. Its generic `priceValidUntil=2026-12-31` is not used as the end of a launch discount. Zazzle's “Comp. value” is not a promised regular price. Missing second prices or deadlines are left absent. Internal scheduling/publication fields remain in SQLite.

## Storefront

`lib/marketplace-prices.ts` fetches only our CDN JSON, with a two-second timeout and five-minute Next data cache. It validates snapshot version, design UUID, marketplace/listing identity, amount, currency and freshness. Legacy observations retain their 36-hour expiry. New observations have a hard 30-day history limit, while only observations verified within 36 hours and before the sale end qualify as current Product/Offer data. CDN and Next caches can delay new publications by roughly ten minutes. Missing, malformed or timed-out data yields no price and does not trigger collection.

`lib/price-policy.ts` matches the uploader's pure policy. At a confirmed sale deadline, server rendering selects the stored regular price without changing `checkedAt`, and labels it “Regular price; check store”. If a discount has no exact deadline, the known regular price is likewise only a labelled fallback after 36 hours. Other older observations show “Last checked price”. After 30 days the history disappears. A new successful collection after the sale restores verified pricing; projected regular prices and old observations are excluded from Product/Offer JSON-LD. The detail page may use another fresh marketplace for its Product. Lists keep their existing all-items-verified rule. All three price-bearing page types have a five-minute revalidation bound. An already-open browser tab changes on navigation/reload, not through a background marketplace request.

Deploy the site before enabling uploader auto-collection. Older site code can still display new version-1 envelopes within its original 36-hour rule. Rolling collection upgrades existing snapshots through real checks; it never retimestamps legacy data to make it look fresh. No paid service, new secret, or database migration is required.

Visible quotes keep each marketplace's own currency. They are not aggregated: stores can sell different shirt variants. Fresh verified quotes come before historical or projected prices, then Redbubble, TeePublic, Tostadora and Zazzle determine priority. The visible primary name, image, amount and currency therefore correspond to the same quote used for Product. The Redbubble CTA and mobile bar retain its exact shirt URL when available. Existing fallback purchase links, affiliate handling, Organization, WebSite, CreativeWork, BreadcrumbList and page metadata are retained.

Catalog, collection and gift detail pages also read the same snapshots for their visible prints, in parallel, using the existing five-minute cache and timeout. They show one validated T-shirt price and seller on each card. Listing selection uses the canonical Redbubble/TeePublic links already in the design, without extra database queries; detail pages retain their full four-marketplace lookup. No marketplace collection runs on a page request.

When at least three unique visible prints all have a fresh verified quote, `ItemList.itemListElement.item` contains the corresponding `Product` and `Offer`, with the same price/currency shown on its card. The Product uses the same identity as the detail page. Smaller lists or incomplete price coverage retain the valid ordinary link list, preserving all visible prints without invented prices or partially populated carousel items. Collection and gift index pages remain lists of collections/pages, not products. Carousel eligibility does not guarantee Google displays the feature.

## Breadcrumbs and other lists

`lib/structured-data.ts` shares page, breadcrumb and Product builders. Inner pages receive a default Home → page `BreadcrumbList`; pages with a more specific trail replace that default. The homepage has no breadcrumb. Catalog collections use Home → Our Designs → collection. Paginated design lists retain absolute positions (page two starts at 16) and the total result count.

`/articles` lists `Article` entries. `/collections` and `/gifts` list collection/gift pages. A gift ideas page groups individual prints; it is not a product bundle sold by this site. These lists remain useful Schema.org data even when Google Rich Results Test does not show a standalone ItemList category.

## Troubleshooting and validation

1. If a local page has no price, check that `NEXT_PUBLIC_IMAGES_CDN` points to the publication destination and that `prices/<UUID>/tshirt-v1.json` exists. Starting Next.js does not collect prices. Publish from the uploader; use `--studio-url http://localhost:3000` when the source endpoint is only available locally.
2. Check `checkedAt`, `expiresAt`, source listing IDs and currency in the snapshot. A price older than 36 hours, an ended sale or a changed marketplace link is excluded. Allow roughly ten minutes for the CDN and Next data caches after publishing.
3. For a product list, check every visible unique print: this implementation emits nested Products only with at least three items and complete fresh price coverage. A missing quote keeps the whole list as named links; available card prices can still appear.
4. Inspect the rendered HTML's `application/ld+json` scripts. Use Schema.org's validator for the full graph and Google Rich Results Test for supported search features. To test localhost, paste the rendered HTML into code mode. A saved result does not refresh when the code changes; start a new test. A production URL test is a separate check after deployment.

Google may recommend reviews, ratings, identifiers, shipping or return fields. Add them only when supported by real, visible information. A valid Product or ItemList does not guarantee a rich result or indexing. See Google's [Product snippets](https://developers.google.com/search/docs/appearance/structured-data/product-snippet) and [carousel beta](https://developers.google.com/search/docs/appearance/structured-data/carousels-beta) documentation.
