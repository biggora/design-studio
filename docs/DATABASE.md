# Спецификация базы данных Design Studio

## 1. Обзор архитектуры хранения данных

Проект **Design Studio** поддерживает две реляционные СУБД:
1. **PostgreSQL / Supabase** — облачная СУБД по умолчанию со встроенным REST API, поддержкой Row Level Security и автоматической генерацией UUID.
2. **MySQL (v8+)** — традиционная реляционная СУБД, подключаемая через пул соединений `mysql2/promise`.

Переключение между базами данных управляется переменной окружения `DATABASE_PROVIDER=supabase` или `DATABASE_PROVIDER=mysql`.

---

## 2. Структура таблиц

Каталог базы данных состоит из двух основных таблиц:
- `studio` — таблица динамических настроек проекта в формате «ключ-значение».
- `designs` — каталог графических работ, метаданных товаров, тегов и ссылок на внешние площадки.

### 2.1 Таблица `studio` (Конфигурация сайта)

Служит для хранения переопределений глобальной конфигурации.

#### Схема PostgreSQL (`init/postgres_tables.sql`)
```sql
CREATE TABLE public.studio (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    key CHARACTER VARYING NULL,
    value TEXT NULL,
    createdat TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now(),
    CONSTRAINT studio_pkey PRIMARY KEY (id)
) TABLESPACE pg_default;
```

#### Схема MySQL (`init/mysql_tables.sql`)
```sql
CREATE TABLE studio (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    `key` VARCHAR(255),
    value TEXT,
    createdat TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

#### Описание полей таблицы `studio`
| Поле | Тип PostgreSQL | Тип MySQL | Nullable | Описание / Пример |
|---|---|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT` | `BIGINT AUTO_INCREMENT` | NO | Первичный числовой идентификатор записи. |
| `key` | `VARCHAR` | `VARCHAR(255)` | YES | Имя ключа конфигурации. Поддерживает точечную нотацию (`social.twitter`, `representation.redbubbleShopUrl`). |
| `value` | `TEXT` | `TEXT` | YES | Значение параметра (строка, URL, ID аналитики). |
| `createdat` | `TIMESTAMP WITH TIME ZONE` | `TIMESTAMP` | NO | Временная метка создания записи (по умолчанию текущее время). |

### 2.2 Таблица `designs` (Каталог дизайнов)

Хранит карточки дизайнов, ссылки на оригинальные изображения, категории, коллекции и атрибуты синхронизации.

#### Схема PostgreSQL (`init/postgres_tables.sql`)
```sql
CREATE TABLE public.designs (
    id UUID NOT NULL DEFAULT gen_random_uuid(),
    "externalId" BIGINT NOT NULL,
    title CHARACTER VARYING NOT NULL,
    description TEXT NOT NULL,
    keywords TEXT NOT NULL,
    "imageName" CHARACTER VARYING NULL,
    "externalImageUrl" TEXT NULL,
    "externalLink" TEXT NULL,
    category CHARACTER VARYING NULL DEFAULT 'no_category'::character varying,
    collection CHARACTER VARYING NULL DEFAULT 'no_collection'::character varying,
    "backgroundColor" CHARACTER VARYING NOT NULL DEFAULT '#FFFFFF'::character varying,
    "backgroundColors" TEXT NULL,
    shared BOOLEAN NULL DEFAULT false,
    props JSON NULL,
    "createdAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now(),
    "updatedAt" TIMESTAMP WITHOUT TIME ZONE NULL,
    CONSTRAINT designs_pkey PRIMARY KEY (id),
    CONSTRAINT designs_externalid_key UNIQUE ("externalId"),
    CONSTRAINT designs_title_key UNIQUE (title)
) TABLESPACE pg_default;
```

#### Схема MySQL (`init/mysql_tables.sql`)
```sql
CREATE TABLE designs (
    id CHAR(36) NOT NULL DEFAULT (UUID()),
    `externalId` BIGINT NOT NULL,
    title VARCHAR(255) NOT NULL,
    description TEXT NOT NULL,
    keywords TEXT NOT NULL,
    `imageName` VARCHAR(255),
    `externalImageUrl` TEXT,
    `externalLink` TEXT,
    category VARCHAR(255) DEFAULT 'no_category',
    collection VARCHAR(255) DEFAULT 'no_collection',
    `backgroundColor` VARCHAR(255) NOT NULL DEFAULT '#FFFFFF',
    `backgroundColors` TEXT,
    shared BOOLEAN DEFAULT FALSE,
    props JSON,
    `createdAt` TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updatedAt` TIMESTAMP NULL,
    PRIMARY KEY (id),
    UNIQUE KEY designs_externalid_key(`externalId`),
    UNIQUE KEY designs_title_key(title)
);
```

#### Описание полей таблицы `designs`
| Поле | Тип PostgreSQL | Тип MySQL | Ограничения | Назначение |
|---|---|---|---|---|
| `id` | `UUID` | `CHAR(36)` | PRIMARY KEY, DEFAULT UUID | Внутренний уникальный идентификатор записи в системе. |
| `externalId` | `BIGINT` | `BIGINT` | UNIQUE, NOT NULL | Уникальный цифровой идентификатор работы на Redbubble (например, `156782390`). Используется для дедупликации при синхронизации. |
| `title` | `VARCHAR` | `VARCHAR(255)` | UNIQUE, NOT NULL | Название дизайна (например, *"Cosmic Cat Embroidery"*). |
| `description` | `TEXT` | `TEXT` | NOT NULL | Полное текстовое описание работы, используемое в карточке и SEO тегах. |
| `keywords` | `TEXT` | `TEXT` | NOT NULL | Список ключевых слов через запятую для поисковой оптимизации. |
| `imageName` | `VARCHAR` | `VARCHAR(255)` | NULL | Имя файла изображения (хэш или slug из CDN). |
| `externalImageUrl`| `TEXT` | `TEXT` | NULL | Прямой URL к качественному превью изображения на CDN Redbubble. |
| `externalLink` | `TEXT` | `TEXT` | NULL | Прямая ссылка на страницу товара в магазине Redbubble. |
| `category` | `VARCHAR` | `VARCHAR(255)` | DEFAULT `'no_category'` | Категория товара (например, `t-shirts`, `stickers`, `posters`). |
| `collection` | `VARCHAR` | `VARCHAR(255)` | DEFAULT `'no_collection'`| Название коллекции (например, `Vintage Animals`, `Geometric Thread`). |
| `backgroundColor`| `VARCHAR` | `VARCHAR(255)` | DEFAULT `'#FFFFFF'` | Основной цвет подложки в HEX-формате. |
| `backgroundColors`| `TEXT`| `TEXT` | NULL | Дополнительная палитра цветов или список доступных оттенков. |
| `shared` | `BOOLEAN` | `BOOLEAN` | DEFAULT `false` | Флаг видимости/публикации в общем каталоге. |
| `props` | `JSON` | `JSON` | NULL | Дополнительные неструктурированные метаданные (источник, исходный URL и т.д.). |
| `createdAt` | `TIMESTAMP WITH TIME ZONE` | `TIMESTAMP` | DEFAULT NOW | Дата добавления работы в каталог. |
| `updatedAt` | `TIMESTAMP` | `TIMESTAMP` | NULL | Дата последнего обновления метаданных или синхронизации. |

## 3. Хранимые функции и процедуры

Для выборки случайных дизайнов (например, для промо-блока на главной странице или динамических рекомендаций) подготовлены оптимизированные функции СУБД.

### 3.1 PostgreSQL (`init/postgres_functions.sql`)

```sql
-- Выборка одного случайного дизайна
CREATE OR REPLACE FUNCTION get_random_design()
RETURNS SETOF designs
LANGUAGE sql
AS $$
    SELECT * FROM designs
    ORDER BY random()
    LIMIT 1;
$$;

-- Выборка трех случайных дизайнов
CREATE OR REPLACE FUNCTION get_random_designs()
RETURNS SETOF designs
LANGUAGE sql
AS $$
    SELECT * FROM designs
    ORDER BY random()
    LIMIT 3;
$$;
```

### 3.2 MySQL (`init/mysql_functions.sql`)

```sql
DELIMITER $$

CREATE PROCEDURE get_random_design()
BEGIN
  SELECT * FROM designs
  ORDER BY RAND()
  LIMIT 1;
END $$

CREATE PROCEDURE get_random_designs()
BEGIN
  SELECT * FROM designs
  ORDER BY RAND()
  LIMIT 3;
END $$

DELIMITER ;
```

## 4. Слой абстракции базы данных (`utils/database.ts`)

Модуль `utils/database.ts` изолирует остальную кодовую базу от низкоуровневых SQL-запросов и специфики драйверов.

### 4.1 `getSiteConfig(): Promise<SiteConfig>`
Запрашивает все записи из таблицы `studio` и собирает их в типизированный объект `SiteConfig` через вызов `mapDataToConfig(props)`.
- **Supabase**:
  ```typescript
  const { data } = await supabase!.from("studio").select("*").returns<ConfigProp[]>();
  return mapDataToConfig(data || []);
  ```
- **MySQL**:
  ```typescript
  const [rows] = await pool!.query<mysql.RowDataPacket[] & ConfigProp[]>("SELECT * FROM studio");
  return mapDataToConfig(rows);
  ```

### 4.2 `fetchDesigns(page, searchQuery, collection, itemsPerPage)`
Выполняет пагинацию и фильтрацию каталога.
- **Входные параметры**:
  - `page: number` — номер запрашиваемой страницы (1-based).
  - `searchQuery: string` — поисковый запрос по названию (регистронезависимый).
  - `collection: string` — фильтр по точному названию коллекции.
  - `itemsPerPage: number` — количество элементов на страницу (по умолчанию 12).
- **Возвращаемое значение**:
  ```typescript
  Promise<{ designs: Design[]; total: number }>
  ```
- **Логика запроса**:
  - В Supabase используется построитель: `.from("designs").select("*", { count: "exact" }).ilike("title", `%${searchQuery}%`).eq("collection", collection).range(start, end)`.
  - В MySQL формируется параметризованный запрос: `SELECT * FROM designs WHERE 1 AND title LIKE ? AND collection = ? LIMIT ? OFFSET ?` с параллельным подсчетом `SELECT COUNT(*)`.

### 4.3 `getDesignById(id: string)`
Запрашивает подробную информацию о конкретном дизайне и до 3 сопутствующих работ из той же коллекции.
- **Сигнатура**:
  ```typescript
  Promise<{ design: Design; relatedDesigns: Design[] } | null>
  ```
- **Логика**:
  - Ищет запись с первичным ключом `id`. Если не найдено — возвращает `null`.
  - По найденному полю `collection` выполняет запрос: `collection = target.collection AND id <> target.id LIMIT 3`.

### 4.4 `fetchCollections(): Promise<string[]>`
Возвращает список всех существующих неуникальных категорий коллекций.
- **Supabase**:
  ```typescript
  const { data } = await supabase.from("designs").select("collection").not("collection", "is", null);
  return Array.from(new Set(data.map(i => i.collection).filter(Boolean)));
  ```
- **MySQL**:
  ```typescript
  const [rows] = await pool.query("SELECT DISTINCT collection FROM designs WHERE collection IS NOT NULL");
  return rows.map(r => r.collection);
  ```

## 5. Пошаговые инструкции по инициализации и миграциям

### 5.1 Инициализация в Supabase (PostgreSQL)

#### Способ 1: Через Веб-интерфейс (Supabase Dashboard)
1. Войдите в панель управления [Supabase](https://supabase.com/dashboard) и откройте ваш проект.
2. Перейдите в левом меню в раздел **SQL Editor**.
3. Создайте новый запрос (**New Query**) и скопируйте содержимое файла `init/postgres_tables.sql`. Нажмите кнопку **Run**.
4. Создайте второй запрос, вставьте содержимое файла `init/postgres_functions.sql` и выполните его.
5. Проверьте создание таблиц в разделе **Table Editor**.

#### Способ 2: Через Supabase CLI
```bash
# Локальный запуск Supabase
npx supabase start

# Применение скриптов схемы
npx supabase db execute --file init/postgres_tables.sql
npx supabase db execute --file init/postgres_functions.sql
```

### 5.2 Инициализация в MySQL

1. Подключитесь к серверу MySQL через консольный клиент или графический инструмент (DataGrip, DBeaver, MySQL Workbench):
   ```bash
   mysql -h your_mysql_host -u your_user -p
   ```
2. Создайте базу данных (если она еще не создана) и переключитесь на нее:
   ```sql
   CREATE DATABASE design_studio CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   USE design_studio;
   ```
3. Примените файлы таблиц и процедур:
   ```bash
   mysql -h your_mysql_host -u your_user -p design_studio < init/mysql_tables.sql
   mysql -h your_mysql_host -u your_user -p design_studio < init/mysql_functions.sql
   ```

### 5.3 Начальное заполнение таблицы `studio`
